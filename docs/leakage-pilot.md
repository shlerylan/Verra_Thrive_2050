# Agricultural Leakage Pilot

Interactive scenarios use the same Python `calculate_leakage` engine as workbook previews. The slider moves immediately and waits 300 ms after the last change before calling `POST /api/projects/{project_id}/leakage/scenario` with `workbook_id`, `year`, and `mitigation_production`. The server reuses the validated stored workbook; it does not require another upload or save scenario changes. Slider bounds, the zero-leakage threshold, and production densities also come from Python. The frontend cancels superseded requests, ignores late responses, and retains labelled previous results on failure with a retry option. The debounce is configurable through `LeakageScenario`'s `debounceMs` prop.

This pilot implements the arithmetic of [VMD0054 v1.0](https://verra.org/wp-content/uploads/2023/09/VMD0054_ARR-Leakage-Module_v1.0.pdf), Equations 1–10, for **one agricultural commodity and one project instance** under [VM0047 v1.0](https://verra.org/documents/vm0047-arr-v1-0/). It accepts three complete historical calendar years immediately preceding the project start year and one to five consecutive monitoring years. Its output is a calculation preview, not a verified VCS result.

Workflow: assign VM0047 v1.0 to a project, select **Agricultural Leakage**, download template v0.2.0, review `Info` and the three input tables, then upload as **Completed Leakage template**. Valid inputs produce a preview and downloadable text report. The original upload is retained with a SHA-256 checksum. Invalid cells are reported by sheet and address; a failed upload is not stored.

Each sheet contains one Excel table: `Info` explains scope, provenance and filling rules; `Parameters` holds shared inputs; `Historical` contains three annual records; `Monitoring` contains up to five. Input cells are yellow and unlocked; headings, source notes and workbook structure are protected against accidental changes. Protection is not a security boundary; the server validates labels, versions, row limits, formulas, numbers and years independently.

The default download is a fixed snapshot of VCS5511 reference workbook values, with original cell references. It preserves start year 2022 and history 2020–2022, and the unchanged sample is accepted for labelled arithmetic replay. Customer workbooks still require the three complete calendar years before project start. Cached biomass and yield formula results are copied as values; their source evidence has not been independently verified. Monitoring covers source rows 15–19 (2023–2027); source row 14 (t=0) is outside this pilot's monitoring period. The server does not read the ignored source workbook at runtime.

**Download test example** returns a separate, clearly marked synthetic workbook with the same four tables. It covers 2023–2027. The 2023 row produces 789.25 t CO2e. Changing `Monitoring!C2` to 400 gives zero for 2023. These are invented inputs, not VCS5511 data. Existing v0.1.0 workbooks remain accepted and are recorded as v0.1.0; new table workbooks are recorded as v0.2.0. Restart the local backend to serve the updated downloads and catalogue.

The calculator uses historical production, annual growth, monitored production and leakage mitigation to estimate foregone production and the part subject to leakage. It then estimates new land, biomass and soil carbon stock change, and year-specific leakage in t CO2e. The displayed total is only an arithmetic sum of preview years; the module labels `LK_t` cumulative while Equation 10 refers to `AL_t` for year `t`, so formal reporting treatment needs review. The template supplies the agricultural default shares of 0.75 and 0.40; users can change them, but supporting evidence for alternative shares is outside this pilot. Blank monitored values are never treated as zero.

The local VCS5511 Leakage workbook provides an arithmetic cross-check: `Historical Production Data!C8:C10` and `C18:C20` contain project and mitigation production; `VCS5511_ARR!F15`, `H15`, `J15`, `K15`, `L15`, `M15`, `O15`, `V15`, and `X15` show the corresponding chain. In that row, mitigation exceeds foregone production, so `M15 = MAX(H15-L15, 0)` and leakage becomes zero. This explains the worksheet's result; it does not verify its input evidence.

Two workbook details require review before using it as a method-compliant fixture: `VCS5511_ARR!C5` gives 2022 as the instance start year, while the historical production table includes 2022; and `K14:K19` repeats a hard-coded monitored mitigation value of 40,803 without a linked record in this workbook. Biomass and soil inputs also need independent source review. The replay displays these limitations with the results.

The pilot excludes fuelwood, multiple commodities, grouped instances, crop rotations longer than three years, applicability and source-evidence review, leakage mitigation agreements, carrying-capacity checks, intensification or supplemental-feed emissions, and other project-level accounting. Formal calculation runs and certified reports remain unavailable. See the source module and tests before extending the scope.
